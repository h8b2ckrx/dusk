# dusk Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build the dusk override layer: one token file driving corner radius
(and later colors) across GNOME Shell, libadwaita apps and GTK3 apps, plus
the Ubuntu 24.04-style Shell modal dialogs.

**Architecture:** SCSS sources in `src/` compile with `sassc` into
`build/gtk4.css`, `build/gtk3.css` and the extension's
`stylesheet-dark.css` / `stylesheet-light.css`. `install.sh` symlinks those
into GTK's user config and Shell's extension folder, and records what it did
so `uninstall.sh` can undo exactly that. Each layer starts with an inventory
of stock Yaru radii, which the owner approves before any rules for that layer
get written.

**Tech Stack:** sassc 3.6 (libsass), bash, Python 3 + PyGObject (GTK 3/4
CSS validation, inventory tool), GNOME Shell 50 ESM extension.

**Spec:** `docs/2026-10-28-dusk-design.md`. Read it before any task.

## Global Constraints

- Target: Ubuntu 26.04.1, GNOME Shell 50.1, Wayland, session mode `ubuntu`;
  GTK 4.22, libadwaita 1.9 (Yaru-patched), GTK 3.24.
- Base is stock Yaru everywhere. No adw-gtk3, no User Themes, no copy of any
  theme file in the repo (inventory summaries are fine; stylesheets are not).
- Every radius, color, spacing and border-width value lives in
  `src/_tokens.scss`. Rule files contain no literal values except bare `0`.
- Never guess selectors: verify each one in Looking Glass (Shell) or GTK
  Inspector (apps). Every top-level rule has a `//` comment above it saying
  what it targets.
- Accent is never set. Shell uses `-st-accent-color`; GTK files never
  declare `--accent-color`, `--accent-bg-color` or `--accent-fg-color`.
- No top bar background or colors. Top bar: radius only.
- Lock screen, GDM, high contrast, Looking Glass: untouched. Ubuntu Dock: corners
  follow the theme (spec decision 17), the rest stays stock; its right-click menus
  follow the menu token.
- Controls: radius only (stock size, flat style, colors).
- Dark first. The light slot exists. Light colors stay empty, except the
  dialog colors (see Task 3).
- GTK3 windows: top corners only, using `$radius-window`. No bottom-corner CSS.
- Extension: UUID `dusk@local`, `shell-version: ["50"]`, no `session-modes`
  key. `extension.js` holds exactly two owner-approved exceptions: dialog
  button rows honour CSS `spacing` (spec §6, Result), and the overview's
  workspace wallpaper honours `.workspace-background`'s CSS radius (spec §4.16).
  Nothing else.
- No other Shell JS patching. If CSS can't do something, stop and ask the owner.
- `install.sh`: idempotent, symlinks, timestamped backups, state file,
  Flatpak step only if Flatpak exists.
- Every task ends with an **owner gate**. Report the files changed
  (`git show --stat HEAD`) and how to revert: `git revert HEAD`, then
  `./install.sh`, then `tools/shell-reload.sh` for Shell (or restart the app
  for GTK). The next task starts only after the owner approves.

## Review Focus

- **Structural square corners in GTK.** Our `gtk.css` runs at user priority,
  so it beats Yaru's corner zeros on linked button groups, entries in linked
  groups and similar. Expected: linked groups stay joined. Pinned in Tasks 9
  and 11.
- **Log Out / Power Off dialogs auto-confirm after 60 seconds.** Testing them
  must never cost the owner their session. Expected: tests use `pkexec true`
  first and always cancel promptly. Pinned in Task 3.
- **Light mode.** The dialog layout applies in light mode too, so its
  divider and hover colors need light values. Expected: dialogs look right in
  light mode. Pinned in Task 3 (test plus check) and Task 12.
- **Accent change in Settings.** That switches the GTK theme to a different
  Yaru variant. Expected: `gtk.css` still applies, and the default dialog
  button follows the new accent. Pinned in Task 12.
- **Top bar neighbours.** Top bar items from other extensions (Vitals, Tasks
  in Panel, Tiling Shell, AppIndicators) and Blur my Shell. Expected: items
  follow the top bar radius, and we never set a top bar background. Pinned in
  Task 1 (output test) and Task 5 (check).

The last path is there because sandboxes can't follow our symlinks otherwise.

Restore or remove the Flatpak overrides file. `rmdir` recorded dirs if empty. Delete the state file. With no state file, it prints `dusk is not installed.` and exits 0. If older backups are left over, it lists them.
  - `tools/shell-reload.sh`: note the time, disable and enable `dusk@local`, wait 1s, print the Shell's log lines since then that match `dusk|stylesheet|css` (case-insensitive). Use the journal query that actually shows gnome-shell's messages on this machine: check `journalctl --user -b` against `journalctl -b _COMM=gnome-shell` once and use whichever works.
